# Поиск и история

Запуск в чате: «Найди новые навыки для UI», «Поищи навыки анимации», «Подбери аналитические навыки». Запуск скриптом: `catalog.py search --query 'анализ данных'`. Сначала журналируется запрос, затем чтение источников, кандидаты либо ошибка. Поиск по именам и темам ограничен заданными репозиториями; для более широкой задачи Codex продолжает обычным веб-поиском первоисточников и сохраняет осмотренные варианты.

Начальные источники: `openai/skills:skills/.curated`, `anthropics/skills:skills`, `remotion-dev/skills:skills`. Это источники публикации, не обещание универсальной совместимости. В `settings.json` можно задать `search_sources: [{"repo":"owner/repo","path":"skills","ref":"main"}]`. Список файлов закрепляется по commit, загружаются только подходящие `SKILL.md`; код и зависимости не запускаются. Кеш списка действует30 минут; `search --refresh-sources` обновляет его. Недоступный источник отмечается отдельно. Если недоступны все — поиск завершается ошибкой, запрос и ошибка сохраняются.

Для веб-/плагин-поиска:

1. `search-start --query '<реальный запрос>'` возвращает ID.
2. Выполни поиск доступными инструментами и открой первоисточники.
3. Сохрани JSON ниже и вызови `search-finish '<id>' --results-file '<файл>'`.

```json
{
  "candidates": [{
    "name": "точное имя",
    "url": "https://example.org/проверенный-первоисточник",
    "summary": "Чем поможет; фактически прочитанное содержание",
    "source_type": "skill",
    "revision": "подтверждённая версия или null",
    "compatibility": "Требования, ограничения и неизвестное"
  }],
  "sources": ["проверенный источник"],
  "warnings": ["ограничения поиска"]
}
```

`source_type` может быть `skill`, `plugin` или `collection`. Повторные URL объединяются. Любой кандидат получает состояние `proposed` и `functional_tested: false`; он не добавляется в установленные карточки. Совпадение имени с установленным — только подсказка, а не доказательство одинакового происхождения.

Перед выбранным изменением — `operation-start`, после — `operation-finish`. Поддержаны установка, замена, обновление, удаление. История сравнивает полный комплект файлов до/после. Неизменившаяся папка помечается `unchanged`, отсутствие требуемого результата — `unproven`; аварийно незавершённый старт остаётся в журнале и не считается успехом. Идентификатор завершённой операции идемпотентен: повторное завершение возвращает существующий результат. Это учёт фактов, не установщик и не разрешение на действие.

`history.jsonl` дописывается под той же блокировкой, что и каталог. Каждая строка связана с предыдущей контрольной суммой; незавершённая/повреждённая запись блокирует дальнейшую запись, не обрезается и не заменяется пустой историей. `history` проверяет чтением цепочку и восстанавливает `HISTORY.md`; Markdown можно пересоздать из JSONL, вручную его не редактировать. Сам журнал не является защитой от намеренной подмены владельцем компьютера. Начало истории — внедрение этого дополнения; прошлые действия не сочиняются задним числом.

Автоматически журналируются установка самого каталога и успешная сверка с наблюдавшимися добавлениями/изменениями/потерей подтверждения. Поисковые записи и история остаются только в личных данных; автоматически отправлять их в Git или внешние сервисы не нужно. Для резервной копии сохраняй весь каталог данных.
