# Данные и обновление

`~/.codex/skill-catalog/settings.json` задаёт `project_roots` (абсолютные пути известных проектов) и необязательный `codex_executable`. Скрипт добавляет текущий проект. Он не сканирует весь диск, историю диалогов, секреты или полные конфиги в отчёт. Добавляй новый известный проект командой `refresh --project-root '<path>'`; это сохраняет путь в настройках. Общие папки `~/.agents/skills`, `~/.codex/skills` и системная папка проверяются отдельно.

`inventory.json` — автоматически обновляемые факты, один объект на логический навык. Разные версии одного плагина — местоположения той же записи. Одинаковые имена независимых навыков из разных проектов получают разные ID. Индекс хранит и исчезнувшие записи. `cache_only` означает только никогда не подтверждённые файлы кеша, `present` — найденную установку; `missing` — отсутствие при последней сверке; `unconfirmed` — ранее известный навык, чью установку сейчас не удалось подтвердить. Только `cache_only` скрывается в обычном обзоре. При ошибке чтения состояние доступности неизвестно; ошибка отражается в `warnings`.

`user.json` — единственный слой пользовательских дополнений, отдельно от инвентаря. Формат:

```json
{
  "schema": 1,
  "skills": {
    "ID из list": {
      "title_ru": "Своё название",
      "origin": "third_party",
      "origin_evidence": "Прямое подтверждение владельца, дата",
      "tasks": ["редактура"],
      "helps": "Чем поможет",
      "output": "Какой результат выдаёт",
      "choose_when": "Когда выбирать",
      "prepare": "Что подготовить",
      "notes": ["Пользовательская заметка"],
      "experience": [{
        "date": "2026-10-22",
        "task": "Конкретная задача",
        "result": "Наблюдавшийся результат",
        "instruction_sha256": "SHA из карточки",
        "skill_sha256": "SHA всего комплекта из карточки",
        "limitations": "Что не проверялось"
      }]
    }
  }
}
```

Классификация без `origin_evidence` не меняет подтверждённое происхождение. `refresh` сохраняет прежние дополнения в `user.json`; при появлении нового навыка может дописать только его исходные направления. Команда `note` только добавляет заметку к существующему ID. Неизвестные пользовательские поля сохраняются. Повреждённый JSON вызывает ошибку, а не заменяется пустыми данными. Обновление защищено файловой блокировкой и атомарной заменой. При оставшейся после аварии `.write.lock` сначала убедись, что нет работающего процесса каталога; не удаляй блокировку автоматически.

Проверенное применение связывается с `skill_sha256` всего комплекта файлов и версией пакета; `installation.json` и Python bytecode не входят. `show` заново читает фактические файлы: изменение справочника или скрипта делает прошлый опыт историческим, даже при неизменном `SKILL.md`. Старые записи опыта только с SHA главного файла также остаются историческими. Исчезновение текущего источника не разрешает выбирать прежнюю сессионную или кешированную версию автоматически.

`curation.json` содержит справочные русские пояснения, но не подменяет пользовательские дополнения. Сторонние навыки и их лицензии не входят в этот комплект. Источник и версию установленного навыка проверяй по его собственной инструкции и сведениям установки.

`session`-снимок для `refresh --session FILE` содержит только `label`, `observed_at` и `skills: [{name, path}]`. Он создаётся из реального списка доступных навыков конкретного чата. Наблюдение ограничено этой сессией; его нельзя выдавать за новую проверку. `skills/list` отдельно запрашивается для каждого известного проекта, с `forceReload: true`; результат сохраняется как датированное обнаружение, а не как результат выполнения навыков.

Для резервной копии достаточно сохранить весь каталог данных. Для восстановления верни его, переустанови навык из Git и выполни обновление. Установка сохраняет предыдущую версию навыка в соседней резервной папке; она не является второй подключённой установкой. Полные пользовательские настройки и заметки в Git автоматически не отправляются.

## Пользовательское происхождение

Кнопка «Изменить происхождение» в карточке сохраняет явное решение владельца: `personal` — «Мои разработки», `third_party` — «Других авторов», `unknown` — «Источник не уточнён», `builtin` — «От OpenAI». Поля `origin` и `origin_evidence` остаются в прежнем `user.json → skills → ID`. Даже `unknown` является сохранённым выбором и не сбрасывается обновлением. Исходные `inventory.source`, местоположения, область проекта и контрольные суммы навыка не меняются; подтверждение владельца хранится отдельно от обнаруженного источника.

Для правки из чата прочитай карточку через `catalog.show_card`: она возвращает `origin_revision`. Вызови `origins.change(directory, skill_id, origin, revision, reason='подтверждение пользователя')`, затем обычный export. Прямое чтение версии: `origins.state(user, inventory, skill_id)`. Без совпадающей версии изменение отклоняется; сначала прочитай свежую карточку и сверь поручение. Версия охватывает происхождение выбранного навыка, поэтому параллельная заметка или изменение другого навыка не теряются. Повторный выбор уже сохранённой группы не добавляет событие; первое явное подтверждение автоматической группы добавляет.

Запись использует общую блокировку и существующую квитанцию `directions-pending.json`; её формат совместим с прежним восстановлением. Событие `skill_origin_changed` содержит навык, прежнюю/новую группу и основание. Менеджер и экспорт Obsidian показывают это изменение в истории. Изменение группы происхождения не делает проектные правила глобальными.

## Автор и ссылки

`user.json → skills → ID → author_profile` хранит отдельный профиль: `{"name":"Имя автора","links":[{"label":"GitHub","url":"https://github.com/автор/проект"}]}`. До восьми ссылок, имя до 160 символов, название ссылки до 80, адрес до 2048; адреса только HTTP/HTTPS без пароля и служебных символов. Полностью пустой профиль `{"name":"","links":[]}` — явное решение пользователя: обновление не подставляет исходные сведения заново. Группа происхождения, установка и область применения от автора не зависят.

Без пользовательской правки начальные сведения берутся из `assets/author-profiles.json` по подтверждённому репозиторию или точному ID, затем из явных исходных метаданных. Название организации и публичный псевдоним допустимы; имя неизвестного человека не угадывается. `author_evidence` объясняет основание. Не путай поставщика пакета и автора конкретного навыка.

Для правки из чата получи свежую карточку `catalog.show_card` и её `author_revision`. Вызови `authors.change(directory, skill_id, profile, revision)`, затем export. Существующий общий механизм записи сохраняет свежие заметки, происхождение и неизвестные поля. Конфликт одновременной правки автора требует перечитать карточку и сверить поручение. Событие `skill_author_changed` хранит прежний и новый профиль. Представления Obsidian показывают имя, рабочие ссылки и изменение в истории.

## Пользовательские направления

В том же user.json дополнительный объект `directions` содержит `schema: 1`, список `items: [{id, title}]` и `assignments: {"ID навыка": ["ID направления"]}`. ID направления не меняется при переименовании. Наличие пустого списка `[]` означает сознательно сохранённый выбор «без направления»; первоначальная классификация и refresh его не заменяют. Первичная инициализация не меняет прежние `skills`, заметки, опыт, избранное и неизвестные поля пользователя. Новые навыки получают исходные назначения только при отсутствии их ключа.

Из интерфейса операции проходят через scripts/directions.py: проверка версии реестра, общая блокировка, объединение с актуальным user.json, запись истории, экспорт. Программный вызов `change(directory, action, revision, ...)` принимает create/rename/assign и возвращает новую revision; после него нужен export. `state(user, inventory)` — чтение; `initialize(directory)` — сохранение исходных тем один раз. Установка навыка реестр не меняет. Удаления тем в этой версии нет.

Прерванная запись хранит проверяемый план в directions-pending.json. Менеджер или `catalog.py directions --initialize` завершает только собственный результат, дописывает одно событие и обновляет представления. Если после прерывания user.json изменён извне, восстановление отказывается заменить свежую правку и сохраняет план для сверки. Не удаляй квитанцию ради обхода конфликта.

## Представления Obsidian

Необязательное `documentation_root` в settings.json указывает существующую абсолютную папку документов. Настройка выполняется только после успешного `catalog.py export --docs-root '<путь>' --save`. Экспорт читает inventory.json, разрешённые пользовательские поля user.json и проверенный history.jsonl. Полные настройки, кеш, резервные копии и неизвестные поля событий не копируются. Пользовательские заметки и запросы входят в предназначенные для них страницы; это личные материалы, раздел `Представления` исключён из Git документов.

Программа владеет только четырьмя фиксированными страницами, `.catalog-export.json` и временной квитанцией `.catalog-export.pending.json` в разделе `Представления`. Метка владельца и контрольные суммы защищают чужой файл и ручные правки от замены; до записи проверяются все четыре страницы. Соседние ручные заметки не изменяются. Повторный экспорт одинаковых данных не меняет ни байты, ни время файлов. Блокировка рабочего хранилища даёт согласованный снимок; читабельные страницы не записываются обратно в JSON. До записи страниц сохраняется проверяемый план старых/новых сумм; после подтверждённой записи квитанция убирается. Собственный частичный результат после аварии узнаётся и обновляется даже при новом изменении исходных данных. Настоящий неизвестный конфликт программа не удаляет: сначала сохрани ручные правки вне раздела, затем повтори export.

Обычные команды CLI выполняют экспорт после изменения; прямой вызов функций Python и внешнее редактирование JSON требуют явного export. Предупреждение экспорта означает, что основная операция уже сохранена, но страницы пока отстают. Запись/чтение в локальной папке подтверждает локальный результат, а не независимую загрузку Google Drive в облако.


## Несколько промптов в пакете навыка

В catalog.json со schema=1 можно задать prompts: список объектов с title и text. Поддерживается до 24 записей, название до 160 символов, текст до 8000. Повторяющиеся тексты объединяются. Это обычный текст для просмотра и копирования, не команды для автоматического запуска. Основной interface.default_prompt из agents/openai.yaml также сохраняется. В каталоге дополнительные промпты появляются после ручной сверки; исходные инструкции и доступность навыка от них не меняются.
