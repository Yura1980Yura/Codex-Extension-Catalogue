# Включение и отключение надстроек

В карточке менеджера есть «Использовать в Codex». Переключение сохраняется сразу,
через документированную команду Codex `skills/config/write`. Затем отдельный процесс
заново читает `skills/list`. Это не проверка списка уже открытого чата: после изменения
нужно перезапустить Codex. Уже прочитанные инструкции не удаляются из истории чата.

Переключатель доступен для каждой подтверждённой установки навыка: личной,
проектной, встроенной, сторонней и внутри плагина, в том числе через ссылку на папку.
Codex сохраняет разрешение по точному пути инструкции. Другая одноимённая копия
в отдельной папке не меняется. Если одну установку используют несколько проектов,
новое разрешение этой установки действует в каждом из них на этом компьютере.
При нескольких копиях выбирайте конкретную часть надстройки; путь виден в источниках.
Отключённый плагин сохраняет приоритет над собственным разрешением его навыка.

При отключении файлы навыка, карточка, заметки, избранное и прежний опыт сохраняются.
Каталог не выдаёт отключённую инструкцию как разрешённую к применению.
Читать имеющийся русский перевод для ознакомления по-прежнему можно.

В history.jsonl записываются прежнее и новое состояние, результат отдельного
обнаружения и требование перезапуска. При неопределённом результате записывается
«Переключение не подтверждено». Настройка перечитывается, успех не предполагается.
Прерванная запись истории хранится в activation-pending.json; открытие менеджера
завершает запись без повторной отправки команды или восстановления старого конфига.

Изменение настроек или инструкции из другого окна обнаруживается по версии файла: устаревший
переключатель перечитывается и предлагает повторить действие. Команда Codex сама
сохраняет свою настройку; менеджер не переписывает полный конфигурационный файл.
Запись сторонним процессом ровно во время команды не блокируется менеджером;
результат перечитывается после её завершения.

MCP, плагины и приложения также имеют переключатели своей фактической области.
Пользовательские настройки записываются через `config/value/write`. Для проектного
`.codex/config.toml` API Codex сейчас возвращает `configLayerReadonly`, поэтому каталог
меняет только выбранный `enabled` в подтверждённом источнике, сохраняя резерв в
приватной рабочей папке. Полный разбор TOML до и после обязан отличаться только
одним булевым значением; остальные значения, комментарии и разрешения сохраняются.
Новый процесс Codex читает действующее значение. Общий конфиг пользователя не меняется.
Если несколько проектов используют один проектный источник, изменение относится к этому файлу.
Ограничения организации не обходятся. У внешней программы нет общего флага Codex;
отключать следует предоставляющее доступ к ней подключение.

Реализация: scripts/activation.py, preview/controls.py, preview/config_edits.py,
POST /api/activation.
Интерфейс принимает ID из каталога, логическое состояние и версию; произвольный
путь из браузера не принимается. Обычные ограничения локального сервера и токена
действуют и для переключателя. Полные настройки Codex не выдаются в браузер и отчёты.
