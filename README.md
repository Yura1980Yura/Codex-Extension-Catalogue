# Codex Extension Catalogue

**Каталог надстроек Codex · Разработчик: 55user3125.**

Локальный браузерный каталог навыков, ресурсов, подключений и проектов **вашего Codex на этой машине**. Происхождение каталога и его собственного навыка — **55user3125**.

[Скачать готовый пакет](https://github.com/Yura1980Yura/Codex-Extension-Catalogue/releases/latest) · [Промпт установки](START-CODEX.txt) · [Изменения](CHANGELOG.md)

## Установка через Codex

Скопируйте в **локальный чат Codex** следующий запрос:

```text
Установи Codex Extension Catalogue — каталог надстроек Codex — из последнего стабильного выпуска
https://github.com/Yura1980Yura/Codex-Extension-Catalogue/releases/latest
Прочитай START-CODEX.txt из этого выпуска и выполни его на этой машине:
проверь архив, разверни каталог, создай ярлык на рабочем столе,
установи и примени skill-catalog для первой сверки, открой каталог.
Сохрани существующие личные данные и настройки. Происхождение — 55user3125.
Сторонние сервисы и платные операции этим поручением не разрешены.
```

Можно передать два файла: **Codex-Extension-Catalogue.zip** и **START-CODEX.txt**. Контрольные суммы находятся в **SHA256SUMS.txt** рядом с ними. Рекомендуемый источник — готовый выпуск с закреплённым тегом, а не снимок меняющейся ветки.

Требования: Python **3.12+**, установленный локальный Codex с `app-server`, браузер. Для самой программы npm и сторонние Python-пакеты не нужны. Облачный чат без доступа к компьютеру не сможет создать на нём ярлык. Если Codex отсутствует в PATH, установщик принимает `--codex-executable`. Если порт 8772 занят другой установкой, задайте свободный порт через `setup.py --port НОМЕР` (он сохранится для ярлыка).

## Что устанавливается

| Объект | Расположение по умолчанию |
|---|---|
| Программа | `~/Applications/Codex-Extension-Catalogue` |
| Навык каталога | `~/.agents/skills/skill-catalog` |
| Исходные личные данные | `$CODEX_HOME/skill-catalog` или `~/.codex/skill-catalog` |
| Снимок и организация текущего интерфейса | `$CODEX_HOME/codex-extension-catalogue-current` |
| Заметки и пожелания | Папка документов пользователя / `Codex Extension Catalogue` либо ранее сохранённый путь |
| Ярлык Codex Extension Catalogue | Рабочий стол пользователя; Windows `.lnk`, macOS `.app`, Linux `.desktop` |

`CODEX_HOME` берётся из окружения процесса установки. При нескольких профилях Codex запускайте установку из нужного профиля: один личный навык и ярлык связаны с одной выбранной установкой. Перенаправление Desktop/Documents учитывается; можно явно передать `--desktop-dir` и `--docs-dir`.

Windows: проверены установка во временный профиль, ярлык и локальный запуск. macOS/Linux: реализованы адаптеры и автоматические проверки формата ярлыков; интерактивный запуск на этих ОС требует проверки на самой машине. Ввод ключа Meshy через Credential Manager доступен только на Windows.

## Что запускает ярлык и как обновляться

Ярлык **Codex Extension Catalogue** запускает установленную локальную программу и открывает каталог в браузере. Он не скачивает новую версию с GitHub при каждом запуске. Открытие каталога не запускает платные операции и не отправляет поручения в чаты.

Обновление **программы**: откройте последний готовый выпуск и снова передайте промпт установки локальному Codex. Установщик обновит программу, сохранив личные данные. Кнопка **«Сверить с Codex»** обновляет список надстроек, проектов и их состояния на этой машине; версию программы она не обновляет.

При первой установке Codex можно поручить самому скачать ZIP и START-CODEX.txt из одного выпуска. Либо скачайте оба файла рядом и вставьте содержимое START-CODEX.txt в чат Codex. Для работы через чат устанавливается собственный навык skill-catalog; ярлык запускает браузерный каталог.

## Как работает каталог

- «Сверить с Codex» перечитывает зарегистрированные проекты, глобальные и проектные источники. Папка проекта может быть недоступна — это отмечается. Автоматической сверки каждые 15 секунд нет.
- Основные состояния разделяют наличие файлов, подтверждение Codex, включение и неизвестное состояние. Сверка метаданных не запускает ваши навыки и не доказывает успешное выполнение внешнего сервиса.
- Проекты берутся из локального реестра Codex. Это адаптер внутреннего формата приложения; при изменении формата появляется предупреждение и сохраняется последний подтверждённый список.
- Есть направления, происхождение, независимые фильтры, избранное, порядок плиток, боковые карточки с описаниями и путями, настройки источников, история и пожелания с готовым поручением для Codex.
- В боковой карточке свойства и теги редактируются нажатием на соответствующий блок. Инструкция, дополнительные документы, ссылки поставщика и вызовы собраны во вкладке «Документация»; пути находятся в «Источниках». Вкладка «Состав» остаётся у надстроек из нескольких частей.
- Для локальной надстройки блок «Область» показывает названия проектов. Нажатие открывает все подтверждённые локальные установки и проектные настройки, состояние включения и пути с открытием папки или копированием. Из окна можно перейти к проекту. Наследуемые глобальные установки и неподтверждённые находки не включаются; названия, наличие проектов и пути берутся из текущей ручной сверки с Codex.
- При ручной сверке перечитываются MD/TXT внутри выбранного пакета навыка: объявленные документы, README и справочные материалы. Новые, изменённые и удалённые файлы учитываются в следующем снимке. Внешние файлы, вложенные отдельные навыки и материалы вне пакета автоматически не копируются. Ограничения чтения показаны в карточке.
- Начальные теги берутся из метаданных пакета и назначения надстройки. Ваш список тегов, включая намеренно очищенный, сохраняется отдельно и имеет приоритет.
- Переключатели доступны для каждой подтверждённой установки навыка: личной, проектной, встроенной, сторонней и внутри плагина, включая ссылки на папки. Меняется разрешение точного пути; одноимённые копии остаются независимыми. MCP, плагины и приложения управляются в своей фактической области. Проектный файл получает только выбранное `enabled`, сохраняется резерв и проверяется чтение Codex. Политики организации сохраняют приоритет; внешняя программа управляется через своё подключение.
- Удаление — отдельное действие с точным объектом, областью и резервом. Встроенные навыки и части плагинов отдельно не удаляются; их можно отключить.
- Пакет содержит программу, шаблоны и собственный навык. Подключения, учётные записи и чужие навыки пользователя не передаются.

## Установка вручную и обновление

Дополнительные репозитории навыков можно указать в личном файле данных каталога `skill-catalog/settings.json` в массиве `skill_repositories`: `repository` в виде `owner/repo`, `branch` и при необходимости `author`. Для проверки такого индекса нужен GitHub CLI `gh` с уже настроенным доступом. Проверка выполняется только при ручной сверке, читает дерево файлов и не меняет репозиторий. Без доступа используется сохранённый индекс с датой и предупреждением. Личные настройки репозиториев не включаются в ZIP. Метаданные `installation.json` и `catalog.json` установленного навыка также используются для ссылок на его источник.

Одноимённый навык связывается с репозиторием только при совпадении инструкции или явно указанном источнике установки. Категория «Мои разработки» сама по себе не подтверждает такую связь. Повреждённый необязательный индекс или недоступный документ не должны останавливать проверку остальных источников; ограничения указываются отдельно.

Из распакованного выпуска, используя Python 3.12+:

```shell
python -X utf8 -B setup.py --verify-only
python -X utf8 -B setup.py --plan
python -X utf8 -B setup.py
```

После установки — из установленной папки:

```shell
python -X utf8 -B deployment.py check --refresh --open
```

Обновление выполняется тем же установщиком из **нового** проверенного ZIP. Существующие заметки, настройки и история не заменяются. Предыдущая программа сохраняется в `~/Applications/.catalogue-backups/`. Если программа или управляемый навык изменены вручную, автоматическая замена останавливается для проверки различий. Резерв программы не заменяет резерв личных документов.

При обновлении с 3.6.0 сохраняются прежние пути программы, снимка и документов, даже если они содержат старое ошибочное название продукта. Новый ярлык получает название Codex Extension Catalogue; прежний управляемый ярлык сохраняется в резерве рабочей папки. Автор и происхождение — 55user3125.

Старые установки Naviki не удаляются: они могут обслуживать существующий запуск Meshy. Для переноса организации старого интерфейса поручите Codex проверить конкретные папки; чужие снимки в новый профиль автоматически не переносятся. Глобальный `AGENTS.md` установщик не переписывает.

Для остановки откройте меню каталога или завершите его локальный сервер. Удаление программы, ярлыка и личного навыка можно поручить Codex по путям из `.catalogue-installation.json`; личные данные и документы сохраняйте отдельно. Автоматического удаления данных нет.

## Разработка и выпуск

Текущий интерфейс: `preview/`; предыдущий — `app/manager/` и `docs/legacy-v2/`. Их инструкции сохранены как история. Запуск исходников: `python -X utf8 -B launch.py`; рабочие данные исходников находятся в `.local/catalog-current/`.

```shell
python -X utf8 -B -m unittest discover -s preview/tests
python -X utf8 -B -m unittest discover -s tests
python -X utf8 -B scripts/build_manifest.py
python -X utf8 -B scripts/build_distribution.py
```

Архив и промпт появляются в `.local/dist/`. Сборка идёт по проверенному MANIFEST.json: `.git`, `.local`, профили, ключи, конфигурация и пользовательские снимки в выпуск не входят. После изменения исходников сначала пересоберите манифест. Правила проверки публикации — [PUBLISHING.md](docs/PUBLISHING.md).

Публичный доступ к коду не устанавливает лицензию на его использование. Лицензии включённых сторонних библиотек сохранены рядом с ними. Расширение условий распространения требует отдельного решения владельца.
